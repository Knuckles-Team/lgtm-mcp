# lgtm-mcp development

This repository owns the LGTM connector's Alertmanager and Grafana API facade,
authentication boundary, action-routed MCP tools, observability ontology and
knowledge-graph ingestion mappings, and packaged connector content. Shared
connector contracts, transports, TLS profiles, and credential helpers belong to
`agent-connector-sdk`; admission, serving, and durable graph state belong to
their owning repositories. Read `AGENTS.md` before changing code and keep
credentials, private endpoints, tenant data, and customer records out of source,
logs, fixtures, and skill content.

## Rapid delivery: the 5-minute contract

Specs are already designed. Deliver small, reviewable slices and cite the owning
spec row in the commit trailer.

- Find the owning row first with `git grep -n "<term>" -- specs` and extend the
  existing spec before adding requirement text.
- Reuse the single `Connector` in `lgtm_mcp/__init__.py`, the `Api` facade in
  `lgtm_mcp/api_client.py`, the Alertmanager and Grafana clients under
  `lgtm_mcp/api/api_client_alertmanager.py` and
  `lgtm_mcp/api/api_client_grafana.py`, with the shared request/TLS boundary in
  `lgtm_mcp/api/api_client_base.py`. Do not create a second API, MCP,
  authentication, or transport plane.
- Preserve `ALERTMANAGER_URL`, `GRAFANA_URL`, `LGTM_MCP_BASE_URL`, `LGTM_TOKEN`,
  `LGTM_MCP_USERNAME`, and `LGTM_MCP_PASSWORD` handling in `lgtm_mcp/auth.py`.
  Keep TLS resolution through `resolve_tls_profile("lgtm")`; never add a
  verification bypass or print credentials.
- Keep the action-routed tools and action allowlists in
  `lgtm_mcp/mcp_server.py`. Preserve the best-effort Alertmanager and Grafana
  ingestion boundary in `lgtm_mcp/kg_ingest.py` and keep source declarations in
  `lgtm_mcp/connector_sources.py` explicit and tenant-neutral.
- Mock Alertmanager/Grafana HTTP responses in local tests; never call a live
  observability stack or use live credentials in a gate.
- Every delivered requirement needs a bound focused test. Generated
  `specs/*/status.json` files come from the shared hooks; never hand-edit them.
- Keep `skills/**`, `ontology/**`, prompts, and `mcp_config.json` coherent with
  the existing package data and the `agent_connector_sdk.connector` entry point
  (`lgtm-mcp = "lgtm_mcp:connector"`). Use the shared Pages dashboard config
  and workflow callers already checked in; do not add a second publisher.

## Setup and gates

Use the pinned environment from `uv sync --locked`, then run the shared gates:

```bash
uv sync --locked
uvx pre-commit run --all-files
uvx pre-commit run --all-files --hook-stage pre-push
```

For focused feedback, run the smallest affected tests with the locked
environment, for example:

```bash
uv run --locked --extra test pytest -q tests/test_lgtm_development_skill.py
uv run --locked --extra test pytest -q tests/test_api_client.py tests/test_mcp_server.py
```

The canonical `.pre-commit-config.yaml` delegates connector-standard, secrets,
spec, tests-fast, and dependency-readiness to `Knuckles-Team/pipelines`. Do not
copy those hooks locally or bypass a failing check.

## Connector-specific checks

- Preserve the Alertmanager and Grafana API method names, endpoint selection,
  action allowlists, and `resolve_action` behavior when changing operations.
  Add focused mocked request tests for a changed provider path.
- Keep the SDK TLS profile and credential handling at the existing client
  boundary. Validate environment settings before provider calls and translate
  provider failures through the existing client boundary.
- Keep `lgtm_mcp/skills/`, `lgtm_mcp/ontology/`, `lgtm_mcp/connectors/`, prompts,
  and `lgtm_mcp/mcp_config.json` in package data. Keep ontology mappings and
  ingestion source metadata neutral and free of tenant-specific values.
- Documentation is published by `.github/workflows/pages.yml`, which calls the
  shared Pages workflow with the checked-in `.github/spec-dashboard.json`.
  Source status records under `specs/` are generated by shared hooks.

## Packaging and publication

`pyproject.toml` declares the `agent_connector_sdk.connector` entry point
`lgtm-mcp = "lgtm_mcp:connector"` and packages `skills/**`, `ontology/**`,
`connectors/**`, prompts, and `mcp_config.json`. For a genuine packaged-content
release, keep the project version, `CHANGELOG.md`, and the editable `lgtm-mcp`
entry in `uv.lock` coherent, then inspect `uv build` output for
`lgtm_mcp/skills/lgtm-mcp-development/SKILL.md`.

The canonical release caller is `.github/workflows/pipeline.yml`: it delegates
Python publication and connector container rendering to the shared pipelines.
Do not commit generated Docker artifacts or add a second release publisher. Do
not claim package, container, or Pages publication from a local build; require
exact-source hosted evidence and the public artifact.

## Delivery discipline

Work in a real Git worktree based on `origin/main`. Inspect the complete diff,
stage only reviewed paths, and verify `git status --short` after every gate. Do
not use `git stash`, `git add -A`, or `git add .`; preserve unrelated working
tree changes. Keep runtime, ontology, status, and generated artifacts outside
this bounded skill slice unless the owning requirement explicitly requires them.
